## UI and safety

- Show both sides' customer, supplier, order, payment allocation counts, receivable and payable totals.
- Nonconflicting additions are reviewed together and retain their distinct IDs. Only true conflicts need individual choices, ten per page. No fuzzy deduplication.
- Show proposed totals and suspicious duplicate groups, with explicit duplicate acknowledgment.
- Download JSON containing the entire original local ledger, local quote inbox, Cloud snapshot and pending reconciliation context. No private device key, Access cookie or token is exported.
- Require the owner to select the downloaded file again; verify SHA-256, exact content and current source serial before enabling Apply. A requested browser download alone is not treated as proof of saving.
- Final confirmation identifies Preview and proposed counts/debt. Local/Cloud changes after review abort safely. Cancel/preview/backup do not change accounting records.
- Use the existing single atomic operation and existing limits. No partial historical upload or engine change. A stage progress overlay does not block receipt application; retry keeps the same operation ID. Persist expected digest/totals for checking again after restart.
- After sending, compare both sides' complete record digests, all summary totals and empty pending queue; never label network failure or mismatching result PASS.

`reconcile.choose` now applies the same ordered choices in one cloned state rather than cloning the complete ledger once per record. Decision semantics and result are unchanged; this removes severe overhead with large recovery histories.
