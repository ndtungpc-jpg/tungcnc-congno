## Vì sao cần hai Pages Functions
Browser trước đây gọi Worker khác tên miền; Android/PWA có thể chặn cookie bên thứ ba. Giữ nguyên hostname Pages Preview để không chuyển IndexedDB. Thêm functions/auth.js và functions/api/[[path]].js trong Pages project hiện có, không tạo tài nguyên Worker/D1 riêng.

Trình duyệt chỉ gọi API cùng origin với credentials same-origin. Pages Functions nhận assertion do Access chèn, chuyển server-side đến đúng Worker Preview cố định; dùng CF_Authorization assertion cookie cho Access ở Worker, cùng audience. Worker vẫn tự kiểm tra RS256, kid/JWKS, issuer, audience, email owner, sub, type=app, iat/nbf/exp. Không tin email từ frontend. JWT không trả về JS hoặc ghi log.

Proxy whitelist chỉ register/device/access/sync cần thiết; không có endpoint mã ghép nối, grant hay bootstrap snapshot. Kiểm tra hostname chính xác làm Functions trả 404 nếu bị đưa sang hostname Production. Access /auth trả về / cố định, không open redirect. API no-store; SW không cache API/auth.
